Release Preflight and export

Before preflight

Confirm:

  • the project has been saved and reopened;
  • exactly one hero is intended for the package;
  • all four required PNG assets are present;
  • skill IDs and prerequisites are stable;
  • required localization is complete;
  • dependency declarations are accurate; and
  • release notes describe the package.

Preflight findings

Blocking findings prevent validated export. Warnings require review but may not block packaging. Use finding codes and navigation actions to locate the affected workspace.

Validated ZIP

The validated ZIP includes:

  • generated ES2 XML;
  • required PNG assets;
  • mod metadata;
  • optional release report;
  • SHA-256 file manifest; and
  • HeroStudioProjectSnapshot.json for lossless Hero Studio reimport.

Clean mod folder

Clean-folder export is intended for local game testing. Desktop output is written to a staging directory and replaces the destination only after staging succeeds.

Previous-export comparison

Load a previous ZIP to identify added, modified, and removed files before publishing an update.

One-hero beta policy

The first public beta exports one hero per mod package. Multi-hero project authoring is retained for future package-generation work, but preflight blocks a multi-hero validated export with MULTI_HERO_EXPORT_UNSUPPORTED.

Steam Workshop

Hero Studio prepares Workshop-ready package content, metadata, and release notes. Direct Workshop upload is not part of the first public beta. Publish through the appropriate game/Steam workflow after testing the generated mod locally.

Schema-8 hero skill release readiness

Current Hero Studio releases require exactly two Innate Skill assignments and the three canonical Generic, Class, and Racial trees. Release Preflight blocks unresolved migrated legacy tree/direct data rather than guessing or silently discarding it. Generated HeroDefinitions and HeroSkillTreeDefinitions use the canonical schema-8 structures.
