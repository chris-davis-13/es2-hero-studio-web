Three-Tree Workspace

Milestone 4.1D makes the schema-8 hero skill system visible and editable as three independent canonical workspaces: Generic, Class, and Racial.

The three canonical roles

  • Generic — the universal hero-skill relationship.
  • Class — the tree associated with the active hero's heroClass relationship.
  • Racial — the tree associated with the active hero's affinity relationship. Multi-affinity racial relationships discovered from local ES2 data remain valid; 4.1D does not collapse them to a name guess.

There is deliberately no fourth Other, Relics, or Innate tree tab. Innate Skills remain the two non-levelable direct assignments authored in Hero Data.

Independent authoring

Each tab reads and writes only hero.skillSystem.trees[generic|class|racial]. Adding, moving, editing, duplicating, deleting, copying, pasting, connecting, validating, or checking progression in one canonical tree does not mutate either of the other two trees.

The selected role also follows skill-effect editing and branch-template capture/application. Branch templates can be targeted explicitly to Generic, Class, or Racial from Template Library.

Legacy schema-7 trees

A migrated schema-7 hero.tree graph remains preserved as compatibility data. If Hero Studio cannot prove its role, 4.1D does not move or relabel it automatically. The Skill Tree workspace shows a preservation notice instead of guessing.

This is intentional lossless migration behavior. Final compatibility/export reconciliation belongs to 4.1F.

Local game data and safety

The 4.1 skill system remains a local-game-data workflow. Desktop discovery and browser-selected ES2 Public/XML data stay read-only; Hero Studio does not modify installed Endless Space 2 files and does not require uploading game data.

Milestone boundaries

  • 4.1D: canonical Generic/Class/Racial authoring workspace.
  • 4.1E: role-aware ES2 catalog integration with those canonical trees.
  • 4.1F: schema-8 export, validation, migration reconciliation, and release readiness.
