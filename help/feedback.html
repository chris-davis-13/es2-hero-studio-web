Public beta feedback

Before reporting a problem

  1. Confirm the application version in Runtime Diagnostics.
  2. Save a copy of the affected project.
  3. Reproduce the issue using the public-beta example project when possible.
  4. Run npm run test:beta only when working from the source repository.
  5. Check Known Limitations and Troubleshooting.

Create a GitHub issue

Open the repository where the beta was downloaded, select Issues, and choose the relevant bug or feature template.

A useful bug report includes:

  • application version;
  • Mac model and macOS version;
  • Apple Silicon or Intel architecture;
  • Basic or Advanced mode;
  • affected workspace;
  • exact reproduction steps;
  • expected result;
  • actual result;
  • whether the issue repeats with the example project;
  • screenshots without private information; and
  • the privacy-safe Runtime Diagnostics report.

Do not post privately owned content unintentionally

Hero images, project files, imported mods, file paths, and exported XML may contain personal or third-party material. Review attachments before posting them publicly.

Recovery-related reports

For save, backup, autosave, or recovery problems, state which of these operations was involved:

  • Save
  • Save As
  • pre-save backup
  • latest autosave
  • previous autosave
  • Recovery Center restore
  • damaged-project fallback
  • Save and Close

Do not delete recovery material until a copy has been made.
