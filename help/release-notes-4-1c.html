ES2 Hero Studio 4.1C — Innate Skills

  • Version: 0.4.1-beta.3
  • Milestone: 4.1C
  • Project schema: 8
  • Data approach: local, read-only Endless Space 2 game data

Added

  • Dedicated Hero Data authoring for Innate Skill Slot 1 and Innate Skill Slot 2.
  • Searchable local picker with a hard maximum of two canonical Innate assignments.
  • Explicit non-levelable Innate semantics: assignments store a skill ID only, with no level/mastery selector.
  • Existing ES2, custom project, and preserved unavailable canonical references can be selected.
  • Direct-assignment observations from indexed HeroDefinitions are shown as evidence without turning Innate into an immutable skill-definition type.
  • Dual direct + tree skills remain valid for Innate assignment.
  • Migration-safe handling for schema-7 projects with more than two old direct-skill IDs.
  • Hero Data guidance for 0/2, 1/2, and 2/2 Innate assignment state.

Compatibility

  • Exactly two canonical Innate slots remain part of schema 8.
  • The old startingSkillIds compatibility list is synchronized from the canonical slots plus preserved legacy extra direct IDs so the current XML exporter continues to work.
  • Legacy extra direct IDs are retained rather than silently erased.
  • The old internal Starting Skills dialog mode remains available for historical regression compatibility, while the visible Hero Data workflow now uses the dedicated Innate mode.

Preserved boundaries

  • Project schema stays at version 8.
  • Installed ES2 files remain read-only and local.
  • Generic/Class/Racial eligibility from 4.1B remains separate from Innate assignment.
  • Three-tree editing remains 4.1D.
  • Full canonical-tree catalog integration remains 4.1E.
  • Final schema-8 release/export readiness remains 4.1F.
