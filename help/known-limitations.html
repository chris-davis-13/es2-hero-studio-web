Known limitations — 0.4.1-beta.6 public beta

One hero per exported mod package

Projects can contain multiple heroes, but validated release export supports one hero per package. Safe multi-hero package generation remains a future milestone.

Schema-7 migration requires review

Hero Studio project schema 8 is authoritative for current releases. Older schema-7 projects are migrated without guessing the role of a previously authored single tree or silently deleting extra direct-skill IDs.

If migrated legacy tree/direct data remains unresolved, Release Preflight blocks schema-8 export until the user explicitly reconciles it.

Unsigned macOS application

The desktop beta is not notarized or code-signed. First launch requires the macOS right-click Open approval process.

Apple Silicon is the primary desktop package

The ARM64 package is the supported public desktop beta. Intel packaging remains an assessment path and requires testing on Intel hardware before distribution.

Native Windows package deferred

No Windows installer is currently published. The browser public beta is the supported cross-platform route while feedback is gathered about any remaining need for Windows-only desktop capabilities.

Browser file access varies

All supported browsers can use project upload/download and validated ZIP export. Direct saving to an approved project file, recent-file reopening, and clean-folder writing depend on browser capability and permission support.

Browser recovery is not permanent storage

The web beta keeps latest and previous autosaves in IndexedDB when available. Browser/private-mode cleanup, storage pressure, or clearing site data can remove them. Download .hsproj backups regularly.

Offline image detection may be limited

The offline application shell caches Hero Studio itself. Automatic face and object detection may still need MediaPipe runtime/model files from external hosts. Manual cropping remains available.

No direct Steam Workshop upload

Hero Studio prepares package files and Workshop metadata but does not upload directly to Steam in this release.

Third-party XML reconstruction is not always lossless

ES2 XML cannot represent all Hero Studio editor metadata. Hero Studio-generated ZIPs include a project snapshot for lossless reimport. Third-party mods without that snapshot are reconstructed from recognized XML and may require manual review.

Unsupported XML requires review

Some imported files or constructs may be preserved rather than represented in guided editors. Advanced mode exposes preservation and semantic-diff information.

No automatic desktop updater

Install later desktop beta versions manually. Keep project files separate from the application bundle. The web beta updates when a new verified deployment becomes active.

No collaborative cloud storage

Projects are local files or browser data. Hero Studio does not provide accounts, shared editing, or cloud synchronization.

Template libraries are local

Desktop and browser template libraries do not synchronize automatically. Browser site-data cleanup can remove browser templates. Use .hstemplates export/import to back up or transfer important templates.

ES2 Skill Catalog and gameplay catalogs

The catalogs reflect the local ES2 data the user indexes. Refresh/re-import after game updates, DLC/content changes, or moving the installation.

Desktop acquisition reads installed ES2 data locally and read-only. Browser acquisition uses user-selected local folders/XML files because browser security prevents silent installed-game scanning.

Existing ES2 skills remain reference-only. Catalog presence is not a guarantee that every skill/hero combination is appropriate; authoritative relationships, eligibility guidance, and Release Preflight should be reviewed.
