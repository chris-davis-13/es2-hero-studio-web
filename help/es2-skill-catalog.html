ES2 Skill Catalog and Guided Skill Selection

Milestone 4.0G adds a searchable catalog of the hero skills available in the user's own Endless Space 2 installation. The goal is to let a first-time hero author choose existing skills by name and description instead of already knowing ES2 internal skill identifiers.

Why the catalog reads the installed game

Hero Studio does not ship a frozen hand-maintained list of game skills. The desktop edition reads the relevant XML from the installed game's Public data, and the browser edition indexes XML that the user explicitly selects. This makes the catalog reflect the user's current base game, installed expansions, and game-data revisions without requiring a Hero Studio update every time the available skill definitions change.

The scan is read-only. Hero Studio never modifies the ES2 installation while building the catalog.

Desktop workflow

  1. Open Skill Library.
  2. Choose Browse Existing ES2 Skills….
  3. On first use, choose Find Endless Space 2 Automatically.
  4. If automatic detection cannot locate the installation, choose Locate Endless Space 2… and select either the ES2 installation folder or its Public data folder.
  5. Hero Studio indexes hero-skill definitions, skill-tree references, relevant GUI elements, and English localization data.
  6. Search or filter the catalog, select one or more checkboxes, and choose Add Selected Skills.

The resulting catalog is cached locally for quick reuse. Use Refresh catalog after installing or removing game content, after a game update, or whenever you want Hero Studio to re-read the installed data.

Browser workflow

A website cannot silently inspect an arbitrary game installation. In the browser edition, open Browse Existing ES2 Skills… and choose either:

  • Choose ES2 Public Folder to index a selected Public directory where folder selection is supported; or
  • Choose ES2 XML Files… to select the relevant XML files directly.

For the richest labels, include the hero-skill definitions, hero skill-tree definitions, GUI elements, and English localization XML. If localization is not available, Hero Studio still lists discovered internal skill IDs and generates a readable fallback name.

Nothing is uploaded. Selected files are read in the browser and the resulting catalog is stored in that browser profile.

Searching and filtering

The picker searches across:

  • localized display name;
  • internal skill ID;
  • description;
  • class associations;
  • faction associations; and
  • skill-tree names in which the skill was found.

Scope filters classify entries as Universal, Class, Faction, or Other ES2 based on the game skill-tree metadata. These labels are guidance rather than hard restrictions. Advanced hero authors can still use unusual combinations when ES2 accepts the referenced skill.

Status filters distinguish:

  • Available — can be added to the active hero;
  • Assigned — already present on the active hero; and
  • Conflicts — an existing custom project skill uses the same internal ID.

A custom-ID conflict is not overwritten automatically. Rename the custom skill or resolve the conflict deliberately before assigning the existing ES2 skill.

Existing ES2 skills versus custom skills

Hero Studio now makes an important distinction:

Existing ES2 skill : Supplied by the installed game. Hero Studio stores a reference to its internal HeroSkillDefinition ID. The game's own effect definitions, GUI entry, and localization remain authoritative.

Custom Hero Studio skill : Authored inside the project. Hero Studio generates the skill definition, simulation descriptor, GUI element, and localization required by the exported mod.

Existing ES2 skills are intentionally read-only for their game-owned ID, name, category, and effects. You may still change their position, tier, and prerequisite relationships inside the custom hero's Skill Tree.

To create a separately authored variation, use Duplicate as Custom in Skill Library. The duplicate receives a new collision-safe ID and becomes editable. Because Hero Studio does not copy opaque game-owned effects out of an existing skill, review and author the custom duplicate's effects before export.

Templates

Existing ES2 skills remain reusable through the Skill Catalog, so a single native catalog entry cannot be saved as a normal custom skill template. Branch templates can preserve existing ES2 references alongside custom skills. When a branch is applied, Hero Studio reuses or recreates the reference-only library entry rather than generating a duplicate game skill definition.

Effect templates cannot be applied directly to an existing ES2 skill. Duplicate the skill as custom first.

Export behavior

The custom Skill Tree XML includes every selected skill, including references to existing ES2 skills. Hero Studio generates HeroSkillDefinition, simulation-descriptor, GUI, and localization entries only for custom skills.

Release validation recognizes the catalog-assigned ES2 IDs as intentional external game references. This avoids the false error that would otherwise occur when a skill appears in the generated tree but is deliberately absent from the mod's generated HeroSkillDefinitions.xml.

The catalog itself is not required at export time. The selected reference metadata is saved in the .hsproj project, so a project using existing ES2 skills can be reopened and exported even after the local catalog cache is cleared.

Safety and privacy

  • Desktop scanning is read-only.
  • The browser reads only files or folders the user selects.
  • Catalog data is stored locally.
  • No catalog or game XML is uploaded by Hero Studio.
  • Clearing the catalog does not remove skills already assigned to a project.
  • The ES2 installation is never changed by this feature.

Release Preflight remains the final authority for project readiness. A catalog entry confirms that Hero Studio found a skill identifier in the indexed game data; it does not guarantee every unconventional class, faction, DLC, or mod combination will behave as intended in every ES2 game state.

4.1B active-hero eligibility

With authoritative HeroDefinitions, the catalog evaluates Generic, Class, and Racial eligibility for the active hero. Direct-only assignments are reserved for 4.1C. Missing evidence is shown as Needs data and remains non-blocking. The catalog defaults to Eligible for authoritative data and All for partial selections.

4.1E canonical tree placement

From Skill Tree, Add from ES2 catalog targets the active Generic, Class, or Racial tree. Relationship evidence is checked for that destination before assignment. Existing ES2 definitions remain read-only and local; direct-only assignments remain part of the Innate workflow.

4.1F release behavior

Existing ES2 skills placed from the local catalog remain reference-only in schema-8 exports. Hero Studio emits project-owned definitions only for custom skills, while preserving native game definitions as external references. Installed Endless Space 2 data remains read-only.
