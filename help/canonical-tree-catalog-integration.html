Canonical Tree Catalog Integration

Milestone 4.1E connects the local ES2 Skill Catalog directly to the schema-8 Generic, Class, and Racial tree workspaces.

Selected-tree eligibility

Catalog eligibility is now evaluated against the tree that is currently open.

  • Generic requires an authoritative Generic tree relationship.
  • Class requires both a Class tree relationship and a match with the active hero's heroClass.
  • Racial requires both a Racial tree relationship and a match with the active hero's affinity.
  • A skill that is eligible somewhere else on the hero is still blocked from the wrong selected tree.
  • Direct-only skills remain outside the tree workflow and belong in the dedicated Innate assignment workflow.
  • Missing or partial relationship evidence remains Needs data and is non-blocking rather than guessed.

Local catalog placement

Choose Add from ES2 catalog in Skill Tree. The catalog identifies the active destination tree and inserts selected ES2 references directly into that canonical schema-8 tree.

Existing ES2 definitions remain read-only. Hero Studio stores a local reference snapshot and never modifies the installed game data.

Source fidelity

Native catalog assignments retain the relationship metadata already indexed in 4.1A, including:

  • tree roles and source tree names;
  • HeroClass and HeroAffinity relationships;
  • direct-assignment evidence;
  • source SkillLevel declarations; and
  • source MasteryLevel declarations.

4.1E does not invent or flatten those level structures into guessed authoring values.

Separation from Innate Skills

The two Innate slots remain in Hero Data and are not tree tabs. Direct-only catalog entries are not inserted into Generic, Class, or Racial trees.

4.1F boundary

4.1E changes in-editor canonical placement only. 4.1F remains responsible for final schema-8 validation, export reconciliation, release preflight, and retirement/reconciliation of the remaining schema-7 compatibility export path.
