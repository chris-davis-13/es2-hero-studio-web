ES2 Hero Studio 4.0N — Real-Time Asset Positioning

  • Version: 0.4.0-beta.15
  • Milestone: 4.0N
  • Project schema: 7

What changed

4.0N removes the visible delay that could occur while repositioning artwork in Hero Asset Studio.

  • Crop dragging now uses a local frame-synchronized canvas preview.
  • Pointer movement no longer commits project state on every input event.
  • The final normalized crop is committed once when a drag finishes.
  • Pointer cancellation restores the saved crop instead of committing an incomplete gesture.
  • Wheel zoom previews immediately and commits after a short pause.
  • Coalesced pointer events are used when the runtime provides them.
  • Desktop Electron and browser editions share the same optimized interaction path.

Why this is faster

Before 4.0N, each pointer movement wrote the crop into global project state. That could trigger project subscribers, history/event processing, stale-output checks, validation, artwork guidance, and React rendering while the pointer was still moving.

4.0N keeps temporary interaction state inside the crop canvas and redraws at most once per animation frame. Project state is updated when the interaction is complete.

Compatibility

Project schema remains version 7. Existing beta.14 projects require no migration. No lower-resolution working copy is introduced. Existing crop normalization, final PNG generation, validation, artwork guidance, Undo/Redo, Release Preflight, and one-hero-per-export semantics remain unchanged.
