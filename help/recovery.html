Reliability and Recovery

Milestone 4.0B strengthens project persistence and failure handling without changing Hero Studio project schema v7 or generated ES2 XML.

Native project saves

Electron project saves use a same-folder temporary file and atomic replacement. When an existing .hsproj is saved, Hero Studio first copies the previous version into:

.hero-studio-backups/

Up to ten pre-save backups are retained for each project. Backups use timestamped .hsproj filenames and can be opened directly if needed.

If the selected project file is malformed, the Electron runtime attempts to open the newest valid pre-save backup. Recovered backups are opened as an unsaved project with no persistent path, requiring Save As so the damaged original is not overwritten accidentally.

Autosave snapshots

Hero Studio keeps two rotating recovery snapshots:

  • Latest autosave
  • Previous autosave

Electron stores them in the application user-data recovery folder. Browser mode stores them in local storage. Autosaves are serialized through a queue so slower writes cannot overwrite newer project state out of order.

The Recovery Center is available from:

Settings → Recovery Center

It can restore, delete, or clear snapshots. Restored projects are deliberately marked unsaved until the user saves them.

Safe application close

Closing the Electron window with unsaved changes opens Hero Studio's normal safety dialog with:

  • Save and continue
  • Discard changes
  • Cancel

Saving must complete before the window closes. Cancelling returns to the project. Discarding an application close removes the discarded autosave so it is not offered again on the next launch.

Atomic release output

ZIP exports are written to a temporary sibling file and renamed into place only after the write succeeds.

Clean-folder exports are created in a staging directory and committed as one folder operation. If the destination mod folder already exists, the previous folder is moved into a timestamped .hero-studio-backups entry. Failed staging operations are cleaned up and do not replace the existing destination.

Crash containment and diagnostics

A global React error boundary presents a recovery screen instead of a blank window. The screen can:

  • Reload Hero Studio
  • Copy a privacy-safe diagnostic report
  • Show technical details

Diagnostic reports include application/runtime information and the error stack. They do not include project content.

Electron main-process errors are also appended to hero-studio-main.log in the application user-data folder. Runtime Diagnostics can display and copy the environment report and test autosave, recovery, and recent-project APIs.

Testing

npm run test:4.0b
