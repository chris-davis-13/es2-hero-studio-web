GitHub Release Procedure Deploy with GitHub Pages

Deploy the web beta with GitHub Pages

The repository includes a manual GitHub Actions workflow that builds, tests, and deploys the verified static browser application.

Before publishing

Confirm in GitHub Desktop:

Current Branch: feature/4.0-beta
No local changes

Run locally:

npm run test:beta
npm run build:web-beta
npm run preview:web-beta

Complete the browser manual checks before publishing.

Enable GitHub Pages

  1. Open the repository on GitHub.com.
  2. Select Settings.
  3. Select Pages under Code and automation.
  4. Under Build and deployment, set Source to GitHub Actions.
  5. Save the setting if GitHub presents a Save button.

Run the deployment

  1. Open the repository’s Actions tab.
  2. Select Deploy ES2 Hero Studio Web Beta.
  3. Select Run workflow.
  4. Choose the tested branch or the final merged release branch.
  5. Select Run workflow again.
  6. Wait for both the build and deploy jobs to succeed.
  7. Open the deployment URL shown by the completed workflow.

The workflow performs:

  • a clean dependency installation;
  • the complete beta regression suite;
  • the verified web-beta build;
  • GitHub Pages artifact upload; and
  • deployment to the github-pages environment.

No application secret or API key is required.

Verify the hosted release

On the published address:

  1. Confirm the official icon and PUBLIC WEB BETA identity.
  2. Create a project.
  3. Add an image.
  4. Save or download the .hsproj file.
  5. Reopen it.
  6. Open Recovery Center and download a recovery copy.
  7. Run Release Preflight.
  8. Export a validated ZIP.
  9. Reload the site and confirm it opens normally.
  10. Disconnect from the network temporarily and confirm the cached application shell opens.
  11. Test at least Safari and one Chromium-based browser before broadly sharing the link.

Updating the site

Commit and push the tested update, then run the same manual workflow again. GitHub Pages replaces the prior deployment after the new build succeeds. The generated service worker uses a versioned cache and removes older Hero Studio caches after activation.

Rolling back

Use the GitHub repository history to restore the last known-good release commit, test it locally, and rerun the workflow. Do not deploy untested working-tree files.

Custom domain later

A custom domain can be configured in Settings → Pages after the default Pages address is verified. The application uses relative production paths, so the same build can operate from a repository subpath or a custom-domain root.
