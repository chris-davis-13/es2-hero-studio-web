GitHub Release Procedure Deploy with GitHub Pages

Deploy the ES2 Hero Studio 0.4.1-beta.6 web beta with GitHub Pages

ES2 Hero Studio deliberately uses two repositories for the public beta:

  • es2-hero-studio — private source/development repository for the desktop application and browser source.
  • es2-hero-studio-web — public static-site repository containing only the generated browser release.

Keep es2-hero-studio private. Do not enable GitHub Pages in the private source repository.

Before publishing

Publish only from final tested release content. In private es2-hero-studio, confirm:

Current Branch: main
No unrelated local changes
Version: 0.4.1-beta.6
Milestone: 4.1F

The release should already have passed:

npm run test:beta
npm run build
npm run release:web-beta
npm run preview:web-beta

Build the verified browser release

From private es2-hero-studio:

npm run release:web-beta

The assembled release is:

release/web-beta/ES2-Hero-Studio-Web-0.4.1-beta.6/

The deployable website is the contents of:

release/web-beta/ES2-Hero-Studio-Web-0.4.1-beta.6/Site/

The outer bundle also contains documentation, checksums, and release metadata. Do not copy the outer bundle itself into the public web repository.

Publish to the separate public repository

Use:

chris-davis-13/es2-hero-studio-web
  1. Open the local clone of es2-hero-studio-web.
  2. Switch to main.
  3. Fetch/pull the current public repository.
  4. Confirm there are no unrelated local changes.
  5. Replace the deployed static-site files in the repository root with the contents of the verified Site/ directory.
  6. Do not copy the outer Documentation/, README-FIRST.md, SHA256SUMS.txt, or web-beta-manifest.json into the deployed root unless they are part of Site/.
  7. Confirm the public root contains generated site files such as index.html, service-worker.js, manifest.webmanifest, .nojekyll, assets/, help/, and web-release verification files.
  8. Review the changes in GitHub Desktop.
  9. Commit with:
Publish ES2 Hero Studio Web 0.4.1-beta.6
  1. Push main.

The public es2-hero-studio-web repository is the only repository intended to host the GitHub Pages site. Preserve its existing known-good Pages configuration; do not enable Pages in the private source repository.

Verify the hosted schema-8 release

After deployment:

  1. Confirm official icon and PUBLIC WEB BETA identity.
  2. Confirm version 0.4.1-beta.6.
  3. Create a fresh hero project.
  4. Assign two Innate Skills.
  5. Exercise Generic, Class, and Racial tree tabs.
  6. Download and reopen the .hsproj.
  7. Download a Recovery Center copy.
  8. Run Release Preflight.
  9. Download a validated ZIP.
  10. Reload normally.
  11. Confirm the cached application shell opens offline after an initial successful load.
  12. Test Safari and at least one Chromium-based browser.

Updating the site

For later releases, build and verify in private es2-hero-studio, copy only generated Site/ contents into public es2-hero-studio-web, review the public diff, commit with the public web release version, and push the public repository.

Rolling back

Restore the last known-good commit in es2-hero-studio-web and verify the hosted application.

Privacy boundary

Never publish private source files, local .hsproj projects, installed Endless Space 2 XML, signing material, credentials, development-only files, or private repository history to es2-hero-studio-web.
