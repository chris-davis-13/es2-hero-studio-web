GitHub Release Procedure Deploy with GitHub Pages

Publish ES2 Hero Studio 0.4.1-beta.6 through GitHub

This procedure publishes the completed 4.1 Complete Hero Skill System public beta.

The desktop/source repository remains private. The browser application is published separately through public chris-davis-13/es2-hero-studio-web.

Do not publish until the release candidate has passed the complete regression suite, production build, Apple Silicon package verification, installed-app checks, browser release verification, and manual schema-8 checks.

1. Prepare and validate the release candidate

Confirm 0.4.1-beta.6, milestone 4.1F, schema 8, and no unrelated local changes.

Run:

npm run test:beta
npm run build

Complete the schema-8 manual acceptance scenarios in Release-Checklist.md.

2. Create and verify the Apple Silicon public-beta bundle

npm run release:public-beta:arm64

Review release verification, public-beta manifest, and SHA-256 checksums. Install the DMG and complete installed-app checks.

3. Create and verify the browser bundle

npm run release:web-beta
npm run preview:web-beta

The deployable static site is:

release/web-beta/ES2-Hero-Studio-Web-0.4.1-beta.6/Site/

4. Preserve the private source repository

Keep private es2-hero-studio private. Do not enable GitHub Pages in it.

The final source release tag must point to the exact tested main content.

5. Publish the browser release from the separate public repository

Follow Web-Deployment-GitHub-Pages.md.

Copy the contents of the verified beta.6 Site/ directory into the root of:

chris-davis-13/es2-hero-studio-web

Review the public-repository diff, then commit with:

Publish ES2 Hero Studio Web 0.4.1-beta.6

Push the public repository and verify the hosted browser application before creating the final source release tag.

6. Create the private source provenance tag

Create private tag v0.4.1-beta.6 in es2-hero-studio against the exact final tested main commit.

This private tag records source provenance only. Do not use a Release in the private repository as the public download page, because beta testers without repository access cannot download private-repository release assets.

7. Publish the public GitHub pre-release from the distribution repository

  1. Open public chris-davis-13/es2-hero-studio-web.
  2. Choose Releases → Draft a new release.
  3. Create public tag v0.4.1-beta.6 against the exact public web commit that passed hosted beta.6 acceptance.
  4. Title: ES2 Hero Studio 0.4.1-beta.6.
  5. Mark as a pre-release.
  6. Use the release notes from private source file docs/Public-Beta-Release-Notes.md.
  7. Attach the verified Apple Silicon DMG and ZIP, desktop checksum/verification files, the browser beta ZIP and appropriate browser manifest/checksum files, and the bundled example .hsproj as appropriate.
  8. Review every attachment for private or third-party content.
  9. Publish from the public distribution repository.

The private and public repositories may use the same version tag name because they are separate repositories. The private tag identifies the tested source commit; the public tag identifies the tested distribution commit.

Publishing the browser site and desktop downloads does not require making the source repository public.

8. Preserve the release state

Published beta artifacts are immutable. Do not replace a published DMG, ZIP, checksum file, public web commit, private source tag, or public distribution tag with corrected content; use a new version/tag for post-publication corrections.
