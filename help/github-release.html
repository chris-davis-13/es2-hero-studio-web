GitHub Release Procedure Deploy with GitHub Pages

Publish the public beta through GitHub

Complete this process only after the 4.0D regression suite, production build, ARM64 packaging, installed-app checks, and public-beta assembly all pass.

1. Commit and push 4.0D

Commit on feature/4.0-beta with:

Complete milestone 4.0D Documentation Branding and Public Beta

Push origin and confirm GitHub Desktop reports no local changes.

2. Create the public-beta bundle

On the Apple Silicon Mac used for final validation, run:

npm run release:public-beta:arm64

Review:

  • release/release-verification-arm64.json
  • release/public-beta/ES2-Hero-Studio-0.4.0-beta.4-arm64/public-beta-manifest.json
  • release/public-beta/ES2-Hero-Studio-0.4.0-beta.4-arm64/SHA256SUMS.txt

3. Decide whether to merge to main

For a durable public release, merge the fully tested beta branch into main before creating the release tag. Do not merge until the final installed application has been tested.

In GitHub Desktop:

  1. Switch to main.
  2. Fetch origin.
  3. Choose Branch → Merge into current branch….
  4. Select feature/4.0-beta.
  5. Confirm there are no conflicts.
  6. Push origin.

If the repository intentionally releases directly from the beta branch, create the tag against the exact tested feature/4.0-beta commit instead.

4. Draft the GitHub Release

On GitHub:

  1. Open the repository.
  2. Choose Releases.
  3. Choose Draft a new release.
  4. Create tag v0.4.0-beta.4 against the tested release commit.
  5. Title the release ES2 Hero Studio 0.4.0-beta.4.
  6. Mark it as a pre-release.
  7. Use docs/Public-Beta-Release-Notes.md as the release notes.
  8. Attach the ARM64 DMG, ARM64 ZIP, SHA256SUMS.txt, and the example .hsproj file.
  9. Review every attachment and publish.

5. Preserve the release state

Do not overwrite attached beta artifacts after publication. A corrected build should receive a new version and tag.

The browser public beta is implemented as milestone 4.0E on feature/4.0-beta. Preserve the tagged 4.0D desktop artifacts, then follow Web-Deployment-GitHub-Pages.md to publish the verified browser release.
