Skill Tree Progression Guidance

Milestone 4.0K expands the existing Check progression workflow into an explainable view of how a hero moves through the current Skill Tree. It is structural guidance for authors. It does not rewrite the tree, enforce a preferred build, or decide whether a hero is balanced.

What the guidance answers

Open Skill Tree → Check progression to review six structural questions:

  1. Can the current entry points reach the tree? Hero Studio uses represented Starting Skills when available. If none are represented, it falls back to Tier 1 skills and then structural roots.
  2. What are the major entry branches? Each entry point is summarized with the number of skills downstream and the longest path depth within that branch.
  3. How do I reach a specific skill? Choose any skill under Explain a skill path to see a shortest prerequisite route from the current entry points.
  4. Which skills act as gateways? A gateway is a reachable non-entry skill that appears on every available route to at least two later reachable skills. This highlights structural bottlenecks; it does not mean the gateway is good or bad design.
  5. Where do paths end? Endpoint skills have no outgoing unlocks. Endpoints can be deliberate capstones, side-grade endings, or incomplete branches.
  6. Are any groups disconnected? A disconnected island is a connected group of skills that cannot currently be reached from the chosen entry paths.

Progression summary

The top of the panel shows:

  • Reachable — skills reachable from current entry points.
  • Entry branches — the entry points used for this analysis.
  • Path depth — the longest shortest route from an entry point to a reachable skill.
  • Gateways — shared dependency points for multiple later skills.
  • Endpoints — skills with no outgoing prerequisite links.
  • Review — findings currently marked for attention.

These values describe the current graph. They are not validation scores.

Starting Skill coverage

When the hero has configured Starting Skills, Hero Studio checks whether those skill IDs are represented as Skill Tree nodes. Represented Starting Skills become the preferred entry points for reachability analysis.

A Starting Skill that is not in the Skill Tree is reported as Consider, not an error. Some mods intentionally grant a Starting Skill outside the visible progression tree.

If no configured Starting Skill is represented, the checker uses Tier 1 nodes as the guided entry points. If no Tier 1 node exists either, structural roots are used so the author can still inspect the tree.

Explain a skill path

Choose a skill from Explain a skill path. For a reachable skill, Hero Studio shows a shortest prerequisite route such as:

Starting Skill → Branch Skill → Specialization → Capstone

Each step is selectable so you can jump to that node in the existing Skill Tree editor.

If the selected skill is not reachable, the panel explains that no current prerequisite route reaches it from the chosen entry points. Review its incoming prerequisites, whether it belongs to an alternate entry branch, or whether the separation is intentional.

Shortest-route guidance is descriptive. A tree may contain several valid routes to the same skill; the panel shows one shortest route for clarity.

Entry branches

Each entry branch starts at one of the analysis entry points. The branch summary reports:

  • the entry skill;
  • the number of skills reachable downstream from that entry; and
  • the branch's maximum path depth.

Branches can overlap when separate prerequisite paths later merge. An overlap is not treated as a problem.

Gateway skills

A gateway skill is a reachable non-entry node that structurally dominates at least two later reachable skills: every currently available route to those later skills passes through that node.

Gateways are useful review points because changing or removing one prerequisite can affect a large portion of a branch. The guidance does not claim that a gateway is too strong, too weak, mandatory in gameplay, or incorrectly balanced.

Endpoints

Endpoint skills have no outgoing prerequisite connections. The panel lists their tier and whether each endpoint is reachable from the current entry paths.

A terminal skill can be a deliberate capstone. Hero Studio does not flag endpoints simply for being endpoints.

Disconnected islands

The checker groups unreachable nodes by undirected structural connection. A multi-skill group outside all current entry paths is described as a Disconnected progression island.

This can indicate:

  • an intended alternate progression route;
  • a branch whose entry prerequisite has not been connected yet;
  • a Starting Skill that exists outside the current tree; or
  • an accidental separation.

The finding remains advisory.

Tier and reachability findings

4.0K preserves the earlier 4.0I progression findings:

  • no Tier 1 entry point;
  • represented or missing Starting Skills;
  • skill may be unreachable;
  • higher-tier skill with no prerequisite;
  • prerequisite that stays in or moves backward to an earlier tier; and
  • prerequisite that skips one or more tiers.

These findings use Review, Consider, or Context language. They do not block export.

Relationship to validation and Release Preflight

Skill Tree Progression Guidance is not a replacement for Hero Studio validation. Existing validation remains responsible for structural correctness such as circular dependencies and invalid references. Release Preflight remains the final export authority.

Progression guidance answers a different question: Does the intended path through this valid structure make sense to the author?

Non-destructive design

The progression engine reads the current Skill Tree, Starting Skills, tiers, and prerequisite edges. It does not call project update APIs and does not add, remove, reconnect, reorder, or retier skills.

Selecting Show skill or a path step only navigates to an existing node.

Compatibility

Milestone 4.0K uses project schema version 7. Existing .hsproj projects do not require migration. The existing 4.0I Hero Wizard, 4.0J Relationship Advisor, templates, ES2 catalog references, browser recovery, desktop recovery, and one-hero export policy remain unchanged.
