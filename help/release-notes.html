ES2 Hero Studio 0.4.1-beta.6

Public desktop and browser beta

ES2 Hero Studio is a dedicated local-first authoring environment for creating and maintaining Endless Space 2 hero mods.

Version 0.4.1-beta.6 completes the 4.1 Complete Hero Skill System and advances Hero Studio releases to project schema 8. Heroes now have first-class Generic, Class, and Racial skill trees plus exactly two canonical Innate Skill assignments, with local ES2 catalog integration and schema-8 release validation.

The beta is available as an unsigned Apple Silicon macOS application and as a browser edition designed for static HTTPS hosting, offline-capable use, and local project processing.

4.1 Complete Hero Skill System

The 4.1 sequence adds:

  • 4.1A — Foundation: schema 8, canonical Generic/Class/Racial containers, two Innate slots, authoritative local HeroDefinition relationship indexing, and lossless schema-7 migration markers.
  • 4.1B — Eligibility: relationship-aware Generic, Class, and Racial eligibility with multi-affinity support and non-blocking Needs data handling.
  • 4.1C — Innate Skills: dedicated authoring for exactly two non-levelable Innate assignments.
  • 4.1D — Three-Tree Workspace: independent live authoring for Generic, Class, and Racial trees without treating Innate as a fourth tree.
  • 4.1E — Catalog Integration: local ES2 Skill Catalog placement directly into the selected canonical tree with destination-specific eligibility.
  • 4.1F — Schema-8 Release Readiness: canonical XML export, explicit legacy reconciliation, release-preflight enforcement, and canonical-tree-aware validation/search/reference tooling.

Release behavior

For schema-8 projects:

  • HeroDefinitions.xml emits exactly two canonical Innate <Skill> references.
  • HeroDefinitions.xml emits exactly three canonical <SkillTree> references.
  • Generic, Class, and Racial project trees are exported separately.
  • Existing ES2 skills remain reference-only and are not regenerated as project-owned definitions.
  • Custom project skills are exported when required, including custom Innate-only definitions.
  • Unresolved migrated schema-7 tree/direct data blocks release rather than being guessed or silently discarded.

Release identity

  • Version: 0.4.1-beta.6
  • Milestone: 4.1F
  • Project schema: 8
  • Application identifier: com.chrisdavis.es2herostudio
  • Desktop package: unsigned Apple Silicon DMG and ZIP
  • Browser package: static HTTPS web application with local-first project storage

Schema-7 Hero Studio projects remain supported through explicit migration into schema 8. Migrated legacy tree/direct data is preserved for review and must be deliberately reconciled before schema-8 release export.

Important limitations

  • one hero per exported mod package;
  • unsigned macOS beta;
  • no direct Steam Workshop upload;
  • no native Windows package at this time;
  • browser security prevents silent installed-game scanning, so browser ES2 game-data acquisition uses user-selected local files/folders;
  • browser persistence is not a substitute for downloaded .hsproj backups; and
  • guided systems provide recommendations rather than automatically making balance or design decisions.

Read Known-Limitations.md before distributing projects or release packages.

Privacy and local processing

Hero project content remains local to the desktop application or browser. The local ES2 catalogs are read-only. Hero Studio does not upload installed ES2 XML or modify installed game files.

Optional image-detection resources are documented separately in Privacy-and-Local-Processing.md.
