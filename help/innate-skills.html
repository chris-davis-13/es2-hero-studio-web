Innate Skills

Milestone 4.1C turns the two schema-8 Innate assignment slots introduced in 4.1A into a dedicated authoring workflow.

What an Innate Skill is

In Endless Space 2, every audited HeroDefinition contains exactly two direct <Skill> references in addition to its three skill-tree references.

Hero Studio models those two direct assignments as Innate Skill Slot 1 and Innate Skill Slot 2.

Innate is an assignment role, not a permanent type on a HeroSkillDefinition. A skill definition may be used as an Innate assignment even if it also appears in a Generic, Class, or Racial tree.

Exactly two non-levelable slots

Schema 8 always contains exactly two canonical Innate slots:

  • Slot 1
  • Slot 2

Each slot stores only a skillId. Innate assignments have no level or mastery selection in Hero Studio. Source SkillLevel and MasteryLevel metadata remains preserved on skill definitions for later tree/level work, but it is not authored on an Innate assignment.

The editor may temporarily show 0/2 or 1/2 assigned while a hero is being authored. Hero Data warns until both slots are filled; this remains guidance rather than a release blocker until the later schema-8 release-readiness milestone.

Searchable local picker

Choose Innate Skills in Hero Data to open the local skill picker. You can select up to two skills from:

  • existing ES2 skills indexed from your own local game data;
  • custom skills authored in the current project; and
  • an unavailable/custom reference that was already occupying one of the canonical Innate slots.

The picker does not apply Generic/Class/Racial eligibility as a restriction because Innate is a separate direct-assignment role.

Skills observed as direct assignments in indexed HeroDefinitions are identified in the detail panel as useful evidence, but Hero Studio does not turn that observation into an immutable skill type.

Legacy direct-skill preservation

A schema-7 project may contain more than two values in startingSkillIds. During schema-8 migration:

  • the first two become the canonical Innate slots;
  • additional direct IDs are preserved in skillSystem.legacy.extraDirectSkillIds;
  • editing the two Innate slots does not silently delete those extras; and
  • preserved extras are locked out of the two canonical picker slots to avoid duplicate direct references.

Hero Data displays a migration note when preserved extra direct IDs exist.

Compatibility export during staged 4.1 work

The existing XML exporter still reads hero.startingSkillIds. 4.1C synchronizes that compatibility list as:

  1. assigned canonical Innate Slot 1/Slot 2 IDs; then
  2. preserved legacy extra direct IDs.

This keeps current XML generation working while the broader schema-8 export transition remains reserved for 4.1F.

Local and read-only game data

The ES2 catalog remains local. Desktop indexing only reads installed game files. Browser indexing reads files/folders explicitly selected by the user. No Endless Space 2 file is modified or uploaded.

Later milestones

4.1C does not implement:

  • the dedicated Generic/Class/Racial three-tree workspace — 4.1D;
  • full role-aware catalog insertion into canonical trees — 4.1E; or
  • final schema-8 export/release readiness — 4.1F.

Project schema remains 8.
