Real-Time Asset Positioning

Milestone 4.0N makes Hero Asset Studio crop positioning responsive in both the desktop and browser editions without changing the saved project format or final image pipeline.

Dragging artwork

While you drag, Hero Studio keeps the temporary crop position local to the crop editor. The canvas redraws through requestAnimationFrame, so the visible crop can follow pointer movement without waiting for project-wide state work.

When the drag finishes, the final normalized crop is committed to the project once. Pointer cancellation restores the last committed crop.

Wheel zoom

Wheel zoom uses the same immediate local preview. A short idle delay groups a burst of wheel events before the final crop is committed to project state.

Desktop and browser

The desktop edition uses Electron/Chromium, so desktop and browser builds use the same frame-synchronized crop path.

Image quality

4.0N does not downscale the source image. The existing source bitmap, crop normalization, and final PNG generation remain unchanged.

Undo/Redo and validation

A completed drag commits one crop update instead of dozens of intermediate updates. Existing history merge keys remain in place, and validation, Changed/Ready status, artwork guidance, autosave, and Release Preflight evaluate the committed crop normally.

Existing controls

Keyboard positioning, crop sliders, copy-crop controls, reset behavior, and output generation remain available. 4.0N specifically optimizes the high-frequency canvas drag and wheel paths that caused visible latency.
