ES2 Hero Studio 4.1A Release Notes

Complete Hero Skill System Foundation

Milestone 4.1A begins the Complete Hero Skill System and advances Hero Studio projects to schema 8 while preserving the local-game-data architecture and existing 4.0 authoring/export behavior.

The schema and taxonomy are grounded in the August 2026 read-only audit of the user's installed Endless Space 2 Public data. That audit found 97/97 HeroDefinition records with exactly three SkillTree references and exactly two direct Skill references. The relationship evidence also showed one common Generic tree, class-specific tree relationships, and affinity/racial tree relationships across the installed hero set.

Added

  • Schema-8 skillSystem foundation on every hero.
  • Three first-class canonical tree containers: Generic, Class, and Racial.
  • Exactly two Innate assignment slots in the canonical schema.
  • Lossless schema-7 migration markers that keep the previous single authored tree unassigned rather than guessing its role.
  • Preservation of any schema-7 direct skills beyond the two canonical Innate slots as legacy compatibility data.
  • HeroDefinition parsing in the local ES2 skill catalog.
  • Relationship-driven tree taxonomy derived from HeroDefinition usage instead of hard-coded tree-name aliases when authoritative data is available.
  • Other handling for special/unassociated trees such as relic-style trees.
  • Direct-skill assignment evidence without permanently declaring a HeroSkillDefinition to be an Innate-only type.
  • Preservation of source SkillLevel and MasteryLevel structures for later 4.1 leveling work.
  • Catalog metadata for tree roles, HeroClass relationships, HeroAffinity relationships, direct assignments, and source leveling structures.
  • Version-2 local skill-catalog cache so older heuristic-only cached indexes are not mistaken for 4.1A relationship-aware indexes.
  • Desktop and browser Public-folder scanning for HeroDefinitions, HeroClassDefinitions, and HeroAffinityDefinitions in addition to existing hero-skill/tree/GUI/localization data.

Compatibility and safety

  • Endless Space 2 remains read-only. Hero Studio only reads selected/installed game data; it does not alter ES2 files.
  • Browser indexing remains local to the browser/device; selected XML is not uploaded.
  • Existing schema-7 hero.tree and startingSkillIds fields remain as 4.1A compatibility fields so the established editor/exporter continue working until the later 4.1 workspace/export milestones move onto the new canonical structures.
  • A schema-7 authored tree is never silently labeled Generic, Class, or Racial.
  • Existing direct-skill lists are preserved verbatim; the first two are mirrored into the canonical Innate slots and any extras are retained in legacy compatibility metadata.

Intentionally deferred

4.1A establishes the data foundation only. Eligibility enforcement, dedicated Innate authoring, the three-tree workspace, full catalog/workspace integration, and final schema-8 export/release readiness remain in later 4.1 milestones.
