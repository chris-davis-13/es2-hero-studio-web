Privacy and local processing

Project data

Hero Studio is designed as a client-side application. Project files, imported mod ZIPs, selected images, generated XML, localization, and exported packages are processed on the user's device. The application does not include an account system, analytics service, advertising system, or project-upload service.

The browser edition is delivered as static application files. Its hosting service necessarily receives ordinary web requests for the application assets, but Hero Studio does not intentionally transmit project content to that host.

Network activity

Most features do not require a network connection after the web application shell is cached. Optional automatic face and object detection retrieves MediaPipe WebAssembly/runtime files and model files from:

  • cdn.jsdelivr.net
  • storage.googleapis.com

Hero Studio does not intentionally send the selected project image to those hosts; detection runs locally after the model resources load. Network tools, operating-system inspection, or future dependency changes may be used to independently verify this behaviour.

Browser storage

The web beta may store:

  • interface preferences in local browser storage;
  • latest and previous recovery snapshots in IndexedDB;
  • user-approved recent project file handles where the browser supports them;
  • service-worker caches for offline application assets; and
  • non-project runtime diagnostics.

Clearing site data removes browser-managed Hero Studio recovery, preferences, approved handles, and offline caches. Private-browsing sessions may discard them automatically. Download project files and recovery copies regularly.

The Request persistent recovery storage control asks the browser to reduce automatic storage eviction. The browser decides whether to grant that request.

Desktop storage

The desktop application may store:

  • interface preferences;
  • recent-project paths;
  • latest and previous recovery snapshots;
  • rotated pre-save backups beside project files;
  • runtime logs; and
  • diagnostic environment information.

Open Help → Open Application Support Folder to inspect desktop application-support data.

Diagnostic reports

Runtime Diagnostics is designed to exclude project content. Review every report before sharing it. Do not attach .hsproj files, imported ZIPs, images, or logs containing sensitive paths unless sharing them is necessary and intentional.

Exported content

Exported mod packages contain the authoring content selected for release, including images, localization, metadata, XML, manifests, and a Hero Studio project snapshot. Inspect the ZIP before public distribution.

ES2 Skill Catalog

The desktop Skill Catalog reads selected or automatically detected Endless Space 2 Public XML files in read-only mode. The browser edition reads only folders/files the user explicitly selects. Parsed catalog metadata is stored locally in the desktop profile or browser storage. Hero Studio does not upload the selected game XML or catalog data. Clearing the catalog cache does not alter the ES2 installation or remove existing skill assignments from saved projects.
