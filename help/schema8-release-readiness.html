Schema-8 Release Readiness

Milestone 4.1F completes the 4.1 Complete Hero Skill System and makes schema 8 authoritative for release generation.

Release contract

A schema-8 hero release now requires:

  1. exactly two canonical Innate Skill references;
  2. exactly three canonical tree relationships — Generic, Class, and Racial;
  3. valid content in each canonical tree container;
  4. no unresolved schema-7 authored tree; and
  5. no preserved extra schema-7 direct-skill IDs.

Hero Studio does not guess or silently discard unresolved legacy data.

XML output

HeroDefinitions.xml writes exactly two <Skill> references from the canonical Innate slots and exactly three <SkillTree> references.

HeroSkillTreeDefinitions.xml writes three project-owned tree definitions with deterministic names based on the hero internal name:

  • <InternalName>_GenericTree
  • <InternalName>_ClassTree
  • <InternalName>_RacialTree

Existing ES2 skills remain references only and are not redefined. Custom project skills used in canonical trees are exported as HeroSkillDefinition records. A custom skill used only as an Innate assignment is also exported as a definition without turning Innate into a permanent skill type.

Legacy reconciliation

A migrated schema-7 project can contain information that schema 8 must not interpret automatically.

Preserved authored tree

In the Three-Tree Workspace, choose the intended canonical tab and use Move legacy tree to …. The move is allowed only when that destination tree is empty, so Hero Studio cannot overwrite canonical work.

Extra direct skills

Hero Data continues to show any direct IDs beyond the two canonical Innate slots. Use Remove preserved extras only after reviewing them. The action is explicit and confirmed.

Until these items are resolved, Release Preflight blocks export with stable schema-8 error codes.

Shared-tool cutover

4.1F also makes canonical trees first-class in:

  • Reference Explorer and orphan detection;
  • localization assignment tracking;
  • Global Search;
  • project validation; and
  • shared-skill update/removal behavior.

A preserved legacy graph remains visible to these systems until it is deliberately reconciled.

Compatibility

The low-level XML builder retains a schema-7 fallback for historical fixtures and reviewed third-party compatibility paths. Current schema-8 release inspection does not use that fallback when unresolved legacy data exists.

Local data policy

The ES2 catalog remains local and read-only. Schema-8 release readiness does not write to installed Endless Space 2 files and does not require uploading game data.
