Complete Hero Skill System

4.1A schema-8 foundation

Hero Studio 4.1 models an Endless Space 2 hero's skill system as five assignment relationships:

  1. a Generic skill tree;
  2. a Class skill tree;
  3. a Racial skill tree;
  4. Innate slot 1; and
  5. Innate slot 2.

This structure is based on a read-only audit of installed Endless Space 2 game data, not on UI assumptions or hard-coded tree names. The audit found 97/97 HeroDefinition records with three SkillTree references and exactly two Innate/direct skill assignments.

Relationship-driven taxonomy

Tree role is a property of the hero-to-tree relationship. When HeroDefinitions are present, Hero Studio derives roles structurally:

  • Generic: the tree referenced by every indexed HeroDefinition.
  • Class: after removing the Generic relationship, the one tree shared by all indexed heroes of a HeroClass.
  • Racial: after Generic and Class relationships are established, the remaining unique normal tree referenced by a hero.
  • Other: a tree definition that is unreferenced or cannot be classified safely from the available relationship evidence.

If HeroDefinitions are missing because the user selected only a partial XML set, the older name-based catalog inference remains a compatibility fallback. It is not the schema-8 authority.

Innate/direct skill semantics

An Innate skill is represented by its direct assignment to a hero, not by permanently changing the underlying HeroSkillDefinition into an innate type. This matters because installed data contains a rare skill that can appear both directly on a hero and in a tree.

Schema 8 therefore stores exactly two canonical Innate assignment slots while keeping the skill definition reusable.

Schema-7 migration

Schema 7 stored one undifferentiated authored graph in hero.tree and a free-form direct-skill list in startingSkillIds. Those fields do not contain enough information to determine whether the authored graph was intended to be Generic, Class, or Racial.

4.1A therefore follows a lossless rule:

  • keep the existing authored graph intact;
  • mark it as an unassigned legacy authored tree;
  • do not copy or guess it into a canonical tree role;
  • mirror the first two existing direct skills into the two canonical Innate slots; and
  • preserve any additional direct-skill IDs as legacy compatibility data.

The compatibility hero.tree and startingSkillIds fields remain live during 4.1A so established 4.0 editor/export behavior is unchanged. Later 4.1 milestones will migrate the user-facing workspace and exporter onto the canonical structures deliberately.

Source leveling metadata

HeroSkillDefinition data is preserved at source fidelity for later 4.1 work. The catalog records SkillLevel declarations and every MasteryLevel declaration (including its Levels value) instead of reducing the source to a guessed single maxLevel number.

Local-game-data guarantee

The desktop app scans installed Endless Space 2 Public XML with read operations only. The browser edition indexes XML selected from the user's local device. No game-data upload is required, and Hero Studio does not write to the Endless Space 2 installation.

4.1B — Hero Skill Eligibility

Eligibility is evaluated per hero rather than stored as an immutable skill type. Generic is universal; Class matches heroClass; Racial matches affinity; direct-only assignments remain for 4.1C; incomplete evidence remains non-blocking Needs data. Schema remains 8. Dedicated Innate authoring, three-tree editing, full canonical-tree catalog insertion, and final schema-8 release readiness remain 4.1C–4.1F.

4.1C — Innate Skills

4.1C makes the two canonical direct assignments editable.

  • Every schema-8 hero retains exactly two Innate slots.
  • Slots store only slot and skillId; no level or mastery value is authored on an Innate assignment.
  • Existing ES2 and custom project skills can occupy a slot because Innate is an assignment role rather than a permanent skill-definition type.
  • Indexed direct HeroDefinition usage is displayed as evidence, not as a hard type restriction.
  • Extra direct IDs migrated from schema 7 remain preserved in legacy.extraDirectSkillIds.
  • startingSkillIds stays synchronized for the current XML export path until 4.1F.

Generic/Class/Racial three-tree editing remains 4.1D; full canonical-tree catalog integration remains 4.1E; final schema-8 release/export readiness remains 4.1F.

4.1D — Three-Tree Workspace

The Skill Tree workspace now operates directly on the three canonical schema-8 containers: Generic, Class, and Racial. Switching tabs changes editor context only; it does not mutate another canonical tree, the two Innate assignments, or the preserved legacy compatibility graph. Branch templates can target a canonical role explicitly. Full role-aware catalog placement follows in 4.1E; final schema-8 validation/export reconciliation remains 4.1F.

4.1F — Schema-8 Release Readiness

4.1F completes the Complete Hero Skill System. Current releases are generated from exactly two canonical Innate assignments and the Generic, Class, and Racial schema-8 trees. Unresolved schema-7 authored-tree or extra-direct data blocks release until the user explicitly reconciles it. Shared validation, reference, localization, search, and release tooling now treat canonical trees as first-class. The local/read-only ES2 data policy remains unchanged.
