Artwork Requirement Guidance

Milestone 4.0L expands the existing Hero Asset Studio artwork check into explainable, per-output guidance. It does not add new ES2 image rules and it does not change project data.

Required outputs

Hero Studio continues to use the established four required PNG outputs:

  • Large Portrait — 360 × 180 PNG
  • Medium Portrait — 180 × 240 PNG
  • Mood Image — 1324 × 712 PNG
  • Mod Icon — 430 × 430 PNG

What the guidance explains

For each output, Review artwork requirements shows:

  • the required dimensions and PNG format;
  • the expected package path;
  • whether the current saved crop enlarges the source image;
  • an approximate framing-pressure cue based on how much of the source frame remains in the tighter output dimension;
  • whether the generated output is missing, changed, invalid, ready, or still worth reviewing; and
  • a suggested next action such as loading a source, reviewing a crop, regenerating an output, or previewing the final PNG.

Source detail and crop guidance

The source-fit calculation follows the same cover-and-zoom geometry used by Asset Studio. If the current crop requires source enlargement, Hero Studio reports the approximate enlargement factor. This is a quality cue rather than an export error. A larger source or less crop zoom may preserve more source detail, but the author decides whether the result is acceptable.

The framing cue estimates how much of the transformed source frame remains visible in the tighter output dimension at the current crop. A low percentage means the output is using a tighter crop and deserves a visual composition check. It does not mean the crop is invalid.

What remains authoritative

Artwork Requirement Guidance is advisory. The existing asset validator and Release Preflight remain authoritative for blocking issues such as missing required outputs, incorrect final dimensions, invalid PNG data, or outputs that no longer match the saved source/crop state.

Preview guides such as Rule of Thirds, Center, Safe Area, and Eye Line remain composition aids. 4.0L does not redefine them as additional ES2 file requirements.

Compatibility

  • Project schema remains version 7.
  • Existing source artwork, crop state, and generated image data are unchanged.
  • The workflow remains local-first and non-destructive.
  • Desktop and browser editions use the same derived guidance.
