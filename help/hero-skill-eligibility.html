Hero Skill Eligibility

Milestone 4.1B adds hero-specific eligibility evaluation to the schema-8 Complete Hero Skill System.

Canonical rules

  • Generic / Universal: eligible for every hero.
  • Class: eligible when the active hero's exact heroClass appears in the authoritative HeroDefinition relationships for that tree.
  • Racial / Affinity: eligible when the active hero's exact affinity appears in the authoritative HeroDefinition relationships for that tree.
  • One Racial tree may map to multiple affinity identifiers; membership is checked against the full set.
  • A direct-only <Skill> assignment is Direct assignment, not a fourth tree. Dedicated Innate authoring remains 4.1C.
  • A rare skill that is both direct and in a tree keeps its tree eligibility.

Unknown is not ineligible

Partial browser-selected XML may omit HeroDefinitions or class/affinity relationships. When the app cannot prove eligibility either way, the result is Needs data. Unknown skills remain non-blocking so incomplete local selections do not create false rejections.

Skill Catalog behavior

The catalog now shows an active-hero summary and filter: Eligible, All, Ineligible, Needs data, and Direct assignment. With authoritative HeroDefinitions it defaults to Eligible; with partial data it defaults to All.

Known ineligible skills and direct-only assignments are prevented from being added as tree skills. Unknown skills remain available with incomplete-data status.

Data and milestone boundaries

All ES2 data remains local and read-only. Project schema remains 8.

4.1B does not implement the two Innate slots (4.1C), the dedicated three-tree workspace (4.1D), full role-aware catalog insertion into canonical trees (4.1E), or schema-8 release/export readiness (4.1F).
